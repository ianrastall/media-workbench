# Python workers

The application bundles CPython 3.14 for metadata/setup coordination; it does not depend on global Python. The coordinator uses the standard library. ML dependencies belong to a separately provisioned Python 3.12 inference profile.

Run `media_worker.py --root <app-or-repository-root>`. It emits a protocol-1 hello, then accepts JSON lines on stdin. Stdout contains protocol events; stderr contains diagnostics.

Operations: `health`, `catalog.list` (bundled recipes), `catalog.search`, `catalog.details`, `installation.status`, `installation.run`, `generate.image`, `upscale.image`, `library.list`, `library.export`, `storage.summary`, `storage.clear`, and `demo.run` (developer text-artifact transport check). `cancel` targets the active request ID and does not emit a second terminal response.

`storage.summary` and `library.export` use the same Rust services that desktop clients call directly. Inventory passes cancellation into native traversal and reads supported profile/model IDs from `profiles/storage-layout.json`. Python does not implement a second inventory walk. Confirmed storage removal still holds the data-folder lock and preserves images/jobs.

`library.list` accepts `dataRoot`, optional `query` (literal, case-insensitive substring of prompt, negative prompt, seed, or job ID), `kind` (`all`, `generate`, `upscale`), `offset` (nonnegative), and `limit` (1–200; defaults to 200 for older callers). It returns `artifacts`, `total`, the effective `offset`, `hasMore`, `problems` (up to 50 recent unfinished jobs, independent of image filters), and `recovered`. The GUI requests pages of 48. `library_index.py` maintains a rebuildable SQLite cache under `library/`, serializes its writers separately from inference, and decodes changed JSON records during refresh. Records, image containment, and file existence remain authoritative; unchanged records need filesystem stat/existence checks, so refresh is still linear in job count. No metadata or pictures are uploaded.

`library.export` accepts `dataRoot`, a completed `jobId`, and an absolute `.png` `destination` outside the resolved data folder. Its ctypes adapter calls the Rust `mw_export_artifact` service, which independently reads/validates the completed job, checks filesystem containment, streams and hashes a temporary copy, and atomically replaces the destination only after checksum verification and the final cancellation check. The GUI calls the same Rust service directly without Python. It returns `path` and `sha256`. The app uses the Windows App SDK save picker (a path-only result; no placeholder file) with its overwrite prompt. The job JSON and original PNG are kept.

`inference_setup.py` owns persistent setup/job state, locks, checksums, runtime installation, and child supervision. Under the data-folder lock it records work left by a dead owner as interrupted; `library.list` returns that count as `recovered`. The desktop client places each worker in a kill-on-close Job Object, so children started here belong to it; do not start them with a breakaway flag. `inference_worker.py` runs only in the private ML interpreter, uses the Hub SDK to fetch a pinned selection, and loads the built-in local safetensors pipeline for inference. See [inference lifecycle](../../docs/inference.md).

Requests are bounded, inputs validated, and metadata responses capped. Public model downloads explicitly disable account tokens. A worker subprocess isolates dependencies and failures; it is not a security sandbox.
