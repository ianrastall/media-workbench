# Stack alignment and acceptance

Reviewed 18 October 2026 against the canonical Markdown edition of **Default Stack Reference for WinUI 3 and Rust Core**, revised 17 October 2026. Its PDF and Word editions are reading copies. The reference supplies architectural defaults and acceptance criteria; it does not make planned capabilities implemented. Repository instructions and the product's actual constraints determine this implementation.

## Scope and deliberate exceptions

Media Workbench is a single-user Windows desktop application for local media creation. The implemented inference path is SD 1.5-family images and Real-ESRGAN upscaling; video remains planned. Public Hub discovery, initial setup, and app updates use HTTPS. Verified inference works offline. There is no hosted service, provider-account integration, or telemetry pipeline. Local MCP access uses an explicitly scoped data folder and launch-time capabilities.

- **Windows 10 22H2 and Windows 11 x64** remain the product targets. Windows 10 is retained for people reusing older NVIDIA computers, but clean-machine validation is pending. The compile target is Windows SDK 26100; the API minimum 19041 is not a promise to support Windows 10 releases earlier than 22H2.
- **x64 only**, rather than the reference's x64/ARM64 default: the bundled interpreters, CUDA runtime profile, installer, and tested native core are x64. Host builds reject other platforms/RIDs, and published checks inspect PE headers. ARM64 needs matching dependency payloads and execution evidence before it can be advertised.
- **Rust 1.97.0** remains pinned rather than copying the reference's later research snapshot. It is the compiler used by the existing implementation and this validation. Review official release/security information before upgrading; do not treat this audit as a support-lifetime assessment.
- **Unpackaged, self-contained, JIT deployment**, with a per-user Inno Setup installer. Both .NET and Windows App SDK runtimes are bundled. Native AOT and MSIX are optional alternatives, not prerequisites for this application. The installer remains unsigned; publisher signing requires a certificate/distribution decision.
- **Stateless, copied-buffer native ABI**, rather than opaque context/result handles. Rust retains no client memory or callbacks; there are no owned native handles requiring SafeHandle wrappers. Long operations use synchronous cancellation callbacks whose managed exceptions are contained. JSON service messages are versioned/bounded; no public ABI record layouts need cross-language offsets yet.
- **Incremental domain migration**: Python still owns substantial job/model readiness, recovery, indexing, and runtime-selection policy. Keeping ML libraries and Hub integration there is intentional; keeping duplicate domain policy in multiple clients is not. Migrate the remaining domain state deliberately through the existing C ABI, without interrupting persistence or verification gates.

## Implementation and remaining evidence

| Reference area | Current evidence | Remaining work |
|---|---|---|
| UI and MVVM | WinUI 3, dark theme, native controls, observable partial properties, UI-free presentation checks | Screen-reader, high-contrast, text-scaling, keyboard and mixed-DPI acceptance matrix |
| Dependency control | SDK 10.0.113 with patch-only roll-forward; Rust toolchain and Cargo.lock; central NuGet versions and per-project locks; CI locked restore | Deliberate servicing reviews; record exact toolchains and dependency inventory with each release |
| Native boundary | ABI 1, LibraryImport, explicit UTF-8 lengths, caller-owned buffers, status/size checks, catch_unwind, real C#/Python boundary checks | A dedicated injected-panic regression and broader shutdown/fuzz coverage; contained panic is not transactional rollback |
| Native loading/build | Absolute app-local DLL loading; x64 host compilation and conflict rejection; build/publish copy metadata; PE architecture checks | Clean-output build on another machine; mixed managed/native breakpoint evidence |
| Work scheduling | UI-free service; background disk/native work; cooperative cancellation; kill-on-close process trees; one active worker request | Durable queue owner/backpressure and warm-child lifecycle; currently global IsBusy deliberately limits concurrency |
| State and persistence | C# owns UI/preferences; Rust owns planning/export/inventory/verification/tidying; JSON jobs and models plus rebuildable SQLite index | Move remaining job/readiness/index ownership into Rust in bounded steps; audit persisted schema upgrades and future-version refusals |
| Failure and data safety | Locked setup/generation, atomic records and export, orphan recovery, retained retry inputs, bounded clean-up, drive-space refusal | Wider interrupted-write/filesystem testing and installer migration evidence |
| Inference | Pinned files/runtime, actual GPU test per runtime choice, fallback, recorded settings, isolated ML child | RTX/Pascal coverage of faster runtime choices; no additional GPU certification from simulated profiles |
| Deployment | Release publish plus shipped core/GUI/MCP self-tests; SHA-256 app updates; CI-only release publication | Clean standard-user Windows 10/11 install/upgrade/offline/update/uninstall tests; signing |
| Performance/debugging | Job inference timing/VRAM evidence and opt-in GPU checks | External startup-to-usable timing, load/inference split, idle CPU/GPU/memory budgets, useful native/managed symbols archived with build metadata |

NuGet central management and locked restore follow the official [central package management](https://learn.microsoft.com/en-us/nuget/consume-packages/central-package-management) and [PackageReference lockfile](https://learn.microsoft.com/en-us/nuget/consume-packages/package-references-in-project-files#locking-dependencies) documentation. Package versions were retained during this change, not upgraded to match a snapshot. The published .NET runtime resolves to 10.0.13; direct NuGet pins are Windows App SDK 2.5.1, Windows SDK BuildTools 10.0.28000.2705, and MVVM Toolkit 8.4.2. The Windows App SDK WinUI component resolves to 2.3.9 in the committed application lockfile. This is a tested combination, not a claim that every newer combination works.

**Discover compatibility and pinned installation** is implemented for public root-level single-file SD 1.5 checkpoints in alpha.14: the Rust metadata plan, bounded header identification, hardware/space/runtime checks, immutable download, preserved notices, native file verification and actual GPU test share the local-import readiness path. Metadata alone never creates a ready model. Direct folder downloads, protected Hub access, other architectures and video remain unsupported in Discover. Next measure load/inference timing and implement the durable queue/warm-child lifecycle; continue independent release/accessibility work alongside it. See [development direction](next-steps.md) for acceptance criteria.
